# 0001. vaultctl запускает CLI-агента, а не работает с vault сам

- **Статус:** Accepted
- **Дата:** 2026-08-19

## Контекст

Задачи над хранилищем Obsidian — клиппинг URL, проектные задачи, брифы, ADR, дневник
работы — уже описаны навыком `obsidian`: инструкции, шаблоны заметок, соглашения о
структуре vault. Навык исполняется внутри CLI-агента (Claude Code, Codex, Grok) и
опирается на его инструменты: Read, Write, Edit, Glob, Grep, WebFetch.

Нужна была точка входа из терминала: «скопировал пост — сохрани в vault» одной командой,
без открытия сессии агента вручную. Вопрос — где проходит граница между этой точкой входа
и логикой работы с заметками.

## Решение

vaultctl не читает и не пишет в vault. Он принимает текст задачи, определяет путь к vault,
запускает CLI-агента подпроцессом с `cwd=vault_path` и `OBSIDIAN_VAULT_PATH` в окружении, и
отдаёт наружу код возврата агента. Все операции над файлами делает агент через навык.

Навык остаётся внешней зависимостью: его содержимое в этот репозиторий не копируется.

## Альтернативы

- **Реализовать операции над заметками в vaultctl** — отверг: логика навыка уже написана и
  переиспользуется другими агентами; копия в Python разошлась бы с оригиналом за месяц, а
  форматы заметок пришлось бы поддерживать в двух местах.
- **Библиотека поверх Agent SDK вместо подпроцесса** — отверг: привязала бы vaultctl к
  одному вендору, тогда как обещание проекта — любой CLI-агент с поддержкой Agent Skills.
  Подпроцесс — общий знаменатель, у которого контракт всего из трёх частей: команда, текст
  задачи, рабочая директория.
- **Обёртка на PowerShell/bash вместо пакета** — отверг: резолв vault, выбор канала доставки
  текста и разбор потока событий уже не помещаются в скрипт, и переносимость теряется.

## Последствия

- (+) Новый тип операции над vault появляется правкой навыка — vaultctl не трогаем.
- (+) Смена агента — это одна переменная `VAULTCTL_AGENT_CMD`.
- (−) vaultctl не может проверить, что навык вообще установлен: он видит только код возврата.
  Задача с неустановленным навыком отработает «успешно» и не даст результата.
- (−) Права на файлы vault определяются агентом, а не vaultctl: набор `--allowedTools`
  становится частью конфигурации (см. `.env.example`).
- Следствие: `WebFetch` обязателен для клиппинга URL — без него навык сохранит заглушку.
