# 0004. npm-шимы `.cmd` запускаются через node, а не через cmd.exe

- **Статус:** Accepted
- **Дата:** 2026-09-02

## Контекст

Дефолтный агент vaultctl — `pi -p`. На Windows npm ставит pi как три шимы в
`%APPDATA%\npm`: `pi` (sh), `pi.cmd`, `pi.ps1`. Нативного `.exe` нет — в отличие от
Claude Code, у которого бинарник нативный, поэтому он запускался из vaultctl «просто так».

`subprocess` без `shell=True` уходит в `CreateProcess`, а тот исполняет только `.exe`/`.com`:
для бат-файлов документация WinAPI прямо требует стартовать `cmd.exe /c`. Итог —
`FileNotFoundError` на команду, которая в шелле работает:

```
Ошибка: CLI-агент «pi» не найден — проверьте --agent-cmd или VAULTCTL_AGENT_CMD
```

## Решение

Перед запуском (`runner.resolve_agent_executable`) имя агента резолвится через
`shutil.which`; если найдена `.cmd`/`.bat`-шима, из её текста regular expression
вытаскивается путь к js-файлу агента (`"%dp0%\node_modules\...\cli.js"`, где `%dp0%` —
каталог шимы), и команда перезаписывается на `node <js>`. Вне Windows и для нативных
бинарников команда не трогается.

Через cmd.exe шиму сознательно не запускаем, хотя это проще: парсер cmd портит
произвольный текст задачи — раскрывает `%ПЕРЕМЕННЫЕ%`, а его правила снятия кавычек в
`/c` ломаются, если в тексте есть двойные кавычки. Задача — данные, и она должна
доезжать до агента байт в байт (см. АДР-0002 про stdin).

## Альтернативы

- **`cmd.exe /d /c <шима> <args>`** — отверг: `%ВАР%` в тексте задачи молча раскроется,
  кавычки в тексте ломают разбор `/c`; воспроизводится только на части текстов, то есть
  хуже падения.
- **`shell=True`** — отверг: тот же cmd-парсер плюс склейка строки вручную, те же ловушки.
- **Парсить шиму на предмет `node.exe` и подставлять его** — отверг как лишнее: `node`
  резолвится через `shutil.which` как обычная команда; шименная логика «если рядом есть
  node.exe» относится к установке, а не к запуску.
- **Требовать нативную установку агента или ручной `VAULTCTL_AGENT_CMD="node <js>"`** —
  отверг как дефолт: ломается из коробки ровно на дефолтном агенте; оставлено как
  подсказка в сообщении об ошибке, когда шиму разобрать не удалось.

## Последствия

- (+) Дефолтный агент работает из коробки на Windows; нативные бинарники не затронуты.
- (+) Текст задачи не проходит через cmd — нет раскрытия переменных и порчи кавычек.
- (−) Парсинг шимы — договорённость с форматом npm, а не контракт: если npm поменяет
  вид шимы, резолв вернёт команду как есть и vaultctl снова скажет «не найден», но уже
  с подсказкой про `node <js-файл>`. Формат стабилен годами и одинаков у старых (`%~dp0`)
  и новых (`%dp0%`) шим — обрабатываются оба.
- (−) Появляется зависимость от `node` в PATH — но она и так есть: шиму создал npm.
  Если node отсутствует, ошибка называется прямо («нужен node в PATH»).
- Следствие: диагностика отказа разделена — незнакомая шима получает свою подсказку
  (`runner._not_found_error`), обычное отсутствие агента — прежнее сообщение.
