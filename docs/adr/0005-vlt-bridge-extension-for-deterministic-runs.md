# 0005. Детерминизм и guardrails автономных pi-прогонов — расширением vlt-bridge

- **Статус:** Accepted
- **Дата:** 2026-09-03

## Контекст

vlt — исполнительный слой: запускает CLI-агента с задачей и никто не смотрит за прогоном.
Для pi это создаёт два риска, которых интерактивная работа не имеет.

1. **Тихий полусбой из-за незагруженного навыка.** pi подключает навык `obsidian` по
   Agent Skills (прогрессивный disclosure: в системном промте — только описание, полный
   SKILL.md модель читает сама, когда сочтёт нужным). Документация pi прямо говорит:
   модели не всегда это делают. Если модель ответит мимо навыка, vlt получит код 0 и
   пустой результат — «успех» без работы.
2. **Отсутствие границ у автономного агента.** Прогон работает без присмотра, модель
   может инструментами `write`/`bash` записать что угодно и куда угодно; сложность
   ошибки не ограничена.

## Решение

Расширение pi `integrations/pi/vlt-bridge.ts` (ставится копированием в
`~/.pi/agent/extensions/`), инертное вне vlt-прогонов: runner помечает прогон
env-маркером `VAULTCTL_RUN=1` рядом с `OBSIDIAN_VAULT_PATH`, расширение работает
только при нём.

- На `before_agent_start` в ход инжектится сообщение: прочитать навык obsidian и
  выполнять задачу строго по нему; операция определяется по префиксу задачи
  (`clip:`, `NameRegister:`). Это не вторая реплика пользователя, а часть того же хода.
- На `tool_call`: записи `write`/`edit` разрешены только внутрь vault, `cwd` и
  временной папки (промежуточным файлам навыка место в temp); заведомо опасные
  shell-команды (`rm -rf /`, `rm -rf ~`, `curl|sh`, `format`, массовый `del`) блокируются
  по консервативному списку. Причина уходит модели в toolResult — она корректирует
  действие, а не ломает прогон.

UI-сценарии (спросить пользователя) сознательно не используются: vlt гоняет агента в
`-p`/`--mode json`, где `ctx.ui` — no-op; там возможны только безусловные блоки.

Логика хэндлеров вынесена в чистые функции уровня модуля (`_internals`) — проверяется
вне pi (см. проверку в интеграции), плюс живые прогоны vlt в тестовом vault.

## Альтернативы

- **Усилить промт в CLAUDE.md vault** — отверг: это уже есть, но не детерминировано;
  ровно этот путь и приводит к тихому полусбою.
- **Разбирать ответ агента в vlt и падать, если навык не отработал** — отверг как
  лечение вместо профилактики: прогон уже потрачен, а распознавание «мимо навыка» по
  тексту ненадёжно.
- **Guardrails в runner'е** — отверг: runner не может влиять на уже запущенного агента,
  он видит только потоки.
- **Всегда включённое расширение для всех сессий pi** — отверг: интерактивные сессии
  не должны получать неожиданные блокировки; поэтому маркер `VAULTCTL_RUN`.

## Последствия

- (+) Активация навыка перестаёт зависеть от решения модели; тихий полусбой закроен.
- (+) У автономного прогона появляются границы: вне vault/temp записи нет, катастрофные
  shell-команды не доходят до шелла.
- (+) Вне vlt-прогонов расширение инертно — интерактивный pi не меняется.
- (−) Артефакт живёт вне репозитория (`~/.pi/agent/extensions/`): после правки нужно
  перекладывать копию; источник правды — `integrations/pi/` в этом репозитории.
- (−) Список опасных команд консервативен: он ловит заведомое, а не всё возможное;
  тонкая фильтрация дала бы ложные блоки на легитимных командах навыка.
- (−) Расширение рассчитано на pi: для других агентов (codex, …) детерминизм и
  guardrails нужно решать их средствами.
