# 0003. vaultctl сбрасывает очередь ввода консоли вокруг запуска агента

- **Статус:** Accepted
- **Дата:** 2026-09-02

## Контекст

Многострочную вставку PowerShell разбирает построчно: первую строку берёт как команду, а
остальные складывает в очередь ввода консоли и выполняет как отдельные команды, когда текущая
команда завершится. Очередь эта общая для процессов одной консоли.

Для vaultctl это означает следующее. Пользователь вставляет пост в терминал, запускается агент
и работает минуту-другую, а по его завершении шелл начинает выполнять хвост вставки как команды:

```
❯ - GLM 5.3 Flash (https://t.me/ai_newz/4726) — Бывшая Ox Alpha ...
ParserError: Missing expression after unary operator '-'.
```

Шквал ошибок из текста заметки — в лучшем случае. В худшем строка окажется исполнимой командой.
Причём приходит это уже после успешной работы агента, поэтому выглядит как поломка vaultctl.

## Решение

Перед запуском агента (после того как текст задачи собран) и ещё раз после его завершения
vaultctl сбрасывает непрочитанный ввод терминала: `FlushConsoleInputBuffer` через ctypes на
Windows, `termios.tcflush` на POSIX. Второй сброс нужен потому, что вставить текст могли и пока
агент работал.

Сброс делается только когда stdin — консоль. Пайп и перенаправленный файл не трогаем: там ввод
это данные, а не хвост вставки. Флаг `--keep-input` отключает сброс целиком.

## Альтернативы

- **Ничего не делать, описать в README** — отверг: проблема срабатывает именно тогда, когда
  README уже прочитан и забыт, а последствие — исполнение чужого текста как команд.
- **Читать очередь и показывать пользователю** — отверг: прочитанное всё равно некуда девать,
  а полезного сигнала в хвосте вставки нет.
- **Просить пользователя не вставлять в терминал** — отверг: под это и сделан `--clipboard`,
  но защита не должна опираться на дисциплину; `-c` не мешает вставить текст по привычке.

## Последствия

- (+) Хвост вставки не доезжает до шелла ни командами, ни ошибками.
- (−) vaultctl трогает состояние, которое ему не принадлежит: если пользователь набирал
  следующую команду, пока агент работал, набранное пропадёт. Отсюда `--keep-input`.
- (−) Поведение платформозависимое и молча деградирует до no-op там, где консоль недоступна.
- Следствие: в ctypes-обёртке обязательны `argtypes`/`restype` — без них 64-битный `HANDLE`
  усекается до int, и сброс тихо не срабатывает (см. `vaultctl/console.py`).
