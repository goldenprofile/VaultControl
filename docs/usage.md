# Справочник: использование vaultctl

README рассказывает о проекте; здесь — детали работы: источники текста задачи,
переменные окружения, выбор агента, коды возврата.

## Длинный текст: не через аргумент

Скопированный пост или статью **нельзя передавать аргументом** — сломается до
того, как vaultctl запустится:

- вставка нескольких строк после открывающей кавычки подвешивает ввод в
  PowerShell: шелл ждёт закрывающую кавычку (`>>`), а выглядит это как зависший
  `vlt`;
- в двойных кавычках PowerShell раскрывает `$`: `стоит $0,15/$0,5` доезжает
  до агента как `стоит ,15/,5`;
- Windows обрывает командную строку на 32767 символах.

Поэтому текст подаётся отдельно, а в аргументе остаётся короткая инструкция:

```bash
# из буфера обмена — основной сценарий «скопировал пост, сохрани в vault»
vlt -c "clip: сохрани этот пост"

# пайпом
Get-Clipboard -Raw | vlt "clip:"
cat post.txt | vlt "clip:"

# из файла
vlt --file post.txt "clip:"

# интерактивно: без аргументов vlt сам попросит текст
# (конец ввода — Ctrl+Z и Enter на Windows, Ctrl+D на Linux/macOS)
vlt
```

Инструкция из аргументов становится первой строкой задачи, текст — блоком под
ней. Источник текста ровно один: `--clipboard`, `--file` и `--stdin`
взаимоисключающие.

**При `-c` вставлять в терминал вообще ничего не нужно** — текст уже в буфере,
vaultctl заберёт его сам. Достаточно `vlt -c`.

## Хвост вставки и очередь ввода терминала

Если многострочный текст всё же попал в терминал, PowerShell берёт первой
строкой команду, а остальные строки остаются в очереди ввода консоли и
выполняются как отдельные команды — когда предыдущая команда завершится. После
долгого запуска агента это выглядит как шквал ошибок из текста заметки:

```
❯ - GLM 5.3 Flash (https://t.me/ai_newz/4726) — Бывшая Ox Alpha ...
ParserError: Missing expression after unary operator '-'.
```

vaultctl сбрасывает очередь ввода терминала — до запуска агента и после его
завершения, — чтобы этот хвост не ушёл в шелл командами. Если вы намеренно
набираете следующую команду, пока агент работает, отключите сброс флагом
`--keep-input`. На пайп и перенаправленный файл это не распространяется: там
ввод — данные, а не хвост вставки.

## Что происходит, пока агент работает

Перед запуском vaultctl печатает в stderr, что именно он делает, — молчание
`pi -p` до финального ответа иначе неотличимо от зависания:

```
▶ vault: D:\Work\Obsidian-Vaults\alpha-llc
▶ агент: pi -p
▶ задача: 4412 символов, 41 строк (аргумент)
```

Флаг `--stream` (или `VAULTCTL_STREAM=1`) показывает и сами шаги агента:

```
▶ агент запущен
  · read(…/skills/obsidian/SKILL.md)
  · bash(curl -sL … -o /tmp/page.html)
  · write(inbox/2026-09-03 - Example Domain.md)
+ готово glm-5.3-flash, $0.00
```

Для этого vaultctl добавляет агенту флаги потока: Claude Code — `--output-format stream-json --verbose`, pi — `--mode json`. Формат разбирается у этих двух; для другого агента vaultctl предупредит и оставит вывод как есть. Строки статуса убираются флагом `--quiet`.

## Переменные окружения

Перед работой vaultctl подгружает `.env`: без `--env-file` файл ищется от текущей рабочей директории вверх по дереву. Переменные, уже заданные в окружении, приоритетнее — `.env` их не перезаписывает.

| Переменная             | Назначение                                        |
|------------------------|---------------------------------------------------|
| `OBSIDIAN_VAULT_PATH`  | путь к vault                                      |
| `VAULTCTL_AGENT_CMD`   | команда запуска CLI-агента                        |
| `VAULTCTL_TIMEOUT`     | ограничение на работу агента, сек (по умолчанию нет) |
| `VAULTCTL_AGENT_INPUT` | канал доставки задачи агенту: `auto`, `arg`, `stdin` |
| `VAULTCTL_STREAM`      | `1` — показывать шаги агента по ходу работы        |

На Windows путь в `.env` пишите без кавычек или в одинарных: в двойных dotenv раскроет escape-последовательности, и путь вроде `D:\Work\alpha` сломается на `\a`.

## Определение vault

Порядок резолва:

1. переменная окружения `OBSIDIAN_VAULT_PATH` — из шелла или из `.env` (должна указывать на существующую директорию);
2. иначе — ближайшая родительская директория текущей рабочей, содержащая папку `.obsidian/`.

Если ни то, ни другое не сработало — vaultctl завершается с ошибкой и кодом `1`.

## Выбор CLI-агента

Команду берём из `--agent-cmd "codex exec"`, иначе из `VAULTCTL_AGENT_CMD`, иначе
встроенное умолчание `pi -p`.

Команда разбирается через `shlex`, текст задачи по умолчанию добавляется последним аргументом. Отсюда два правила, которые легко нарушить:

**Флаг со списком значений не должен стоять последним.** Он проглотит задачу:

```bash
# ✗ агент ответит «Input must be provided» — --allowedTools забрал текст задачи
--agent-cmd "pi -p --allowedTools WebFetch,Read,Write"

# ✓ -p последний, задача уходит агенту
--agent-cmd "claude --allowedTools WebFetch,Read,Write -p"
```

**Путь с обратными слэшами берите в кавычки** — иначе `shlex` их съест и `C:\bin\claude.exe` превратится в `C:binclaude.exe`:

```bash
--agent-cmd '"C:\Users\me\.local\bin\claude.exe" -p'
```

**npm-шимы `.cmd` vaultctl разворачивает сам.** На Windows агенты из npm (pi) — это `.cmd`-шимы, которые subprocess запустить не может («pi есть в PATH, но vaultctl его не находит»). vaultctl сам вытаскивает из шимы путь к js-файлу и запускает агента через node — ничего прописывать не нужно (подробнее — [ADR-0004](adr/0004-launch-npm-cmd-shims-through-node.md)). Если шима не разобралась, vaultctl подскажет задать `VAULTCTL_AGENT_CMD` в виде `"node <js-файл агента>"`.

Для клиппинга URL агенту нужен инструмент загрузки страниц (у Claude Code — `WebFetch`): без него страница не скачается и в vault ляжет заглушка вместо разбора. Готовая команда — в `.env.example`.

## Расширение pi: vlt-bridge

Для агента pi есть сопроводительное расширение (`integrations/pi/vlt-bridge.ts` в репозитории, устанавливается копированием в `~/.pi/agent/extensions/`): детерминирует работу автономных прогонов.

- **Гарантированная активация навыка.** Прогрессивный disclosure не гарантирует, что модель откроет SKILL.md; для unattended-прогона это тихий полусбой — vlt вернёт 0 с пустым результатом. Перед первым ответом модели расширение инжектит инструкцию прочитать навык и работать строго по нему (операция определяется по префиксу задачи: `clip:`, `task:` — записать задачу, не выполняя её, `NameRegister:`).
- **Guardrails.** Записи инструментами `write`/`edit` разрешены только внутрь vault и временной папки; заведомо опасные shell-команды (`rm -rf /`, `curl | sh`, `format`, массовые `del`) блокируются. Причина блокировки уходит модели, чтобы она скорректировала действие.

Расширение включается только на vlt-прогонах: runner ставит агенту `VAULTCTL_RUN=1`, вне их оно инертно и обычные сессии pi не трогает. Решение зафиксировано в [ADR-0005](adr/0005-vlt-bridge-extension-for-deterministic-runs.md).

## Канал доставки задачи агенту

`--agent-input` (или `VAULTCTL_AGENT_INPUT`) выбирает, как задача попадёт к агенту:

| Значение | Поведение                                                             |
|----------|------------------------------------------------------------------------|
| `auto`   | по умолчанию: аргументом, пока командная строка помещается в лимит ОС; длинный текст уходит в stdin |
| `arg`    | всегда последним аргументом                                            |
| `stdin`  | всегда потоком — агент должен уметь читать задачу из stdin (`pi -p` умеет) |

В stdin задача пишется байтами в UTF-8: в текстовом режиме Python на Windows
заменил бы `\n` на `\r\n`, и агент получил бы не тот текст.

## Опции

| Опция            | Описание                                                      |
|------------------|---------------------------------------------------------------|
| `-c/--clipboard` | взять текст задачи из буфера обмена                            |
| `-f/--file`      | взять текст задачи из файла                                    |
| `--stdin`        | взять текст задачи из stdin (при пайпе включается сам)         |
| `--agent-cmd`    | команда запуска CLI-агента                                     |
| `--agent-input`  | канал доставки задачи агенту: `auto`, `arg`, `stdin`           |
| `--env-file`     | путь к конкретному `.env` вместо поиска вверх по дереву        |
| `--timeout`      | ограничение на работу агента в секундах                        |
| `--stream`       | показывать шаги агента, если формат его потока известен        |
| `-q/--quiet`     | не печатать строки статуса перед запуском                      |
| `--keep-input`   | не сбрасывать очередь ввода терминала                          |

## Коды возврата

| Код         | Значение                                                        |
|-------------|-----------------------------------------------------------------|
| `0`         | агент отработал успешно                                          |
| `1`         | не определён vault, нет указанного `--env-file`, кривой таймаут  |
| `124`       | агент не уложился в `--timeout` и был остановлен                 |
| `127`       | команда агента не найдена                                        |
| прочие      | код возврата запущенного CLI-агента                              |
