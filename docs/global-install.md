# Установка vlt как глобальной команды

Чтобы `vlt` (и `vaultctl`) были доступны из любого места в терминале, не требуя
`cd` в директорию проекта.

## Способ 1: uv tool install (рекомендуется)

`uv tool` устанавливает пакет в изолированное окружение и добавляет его
исполняемые файлы (entry points из `[project.scripts]`) в `PATH` автоматически.

```powershell
# Из директории проекта
cd <путь-к-репозиторию>

# Установить как глобальный инструмент (редактируемый режим — изменения в коде
# подхватываются сразу)
uv tool install --editable .

# Всё. Теперь можно запускать из любой папки:
vlt "сохрани ссылку https://example.com"
vaultctl "добавь задачу в список покупок"
```

Проверить, что установка прошла:

```powershell
vlt --help
```

> **Примечание:** `uv tool install` кладёт исполняемые файлы в каталог, который
> `uv` добавляет в `PATH` при установке. Если команда `vlt` не находится —
> перезапустите терминал или добавьте `%USERPROFILE%\.local\bin` в `PATH` вручную
> (см. `uv tool list`).

### Обновление после изменений в коде

```powershell
cd <путь-к-репозиторию>
uv tool install --editable .   # переустановить
```

### Удаление

```powershell
uv tool uninstall vaultctl
```

### Если uv tool недоступен

Убедитесь, что используется достаточно свежая версия `uv`:

```powershell
uv --version        # должно быть 0.3.0 или новее
```

В 0.2.x был только preview `uv tool run`; `uv tool install` появился в 0.3.0.

## Способ 2: pipx

```powershell
cd <путь-к-репозиторию>
pipx install -e .
```

`pipx` делает то же, что `uv tool install`: изолированное окружение плюс команды в `PATH`.
Берите его, если `pipx` уже стоит, а `uv` — нет.

> `uv pip install -e .` сюда **не** подходит: он ставит пакет в `.venv` проекта, и `vlt`
> из другой папки по-прежнему не найдётся. Это эквивалент `uv sync`, а не глобальная установка.

## Настройка окружения

При запуске из произвольной директории `vlt` не найдёт `.env` файл проекта
(поиск идёт от текущей папки вверх). Есть три варианта:

### Вариант А: Глобальные переменные окружения (рекомендуется)

Задать переменные в профиле PowerShell (`$PROFILE`) или через системные
переменные:

```powershell
# PowerShell $PROFILE
$env:OBSIDIAN_VAULT_PATH = "D:\Obsidian\MyVault"
$env:VAULTCTL_AGENT_CMD  = "pi -p"
```

Или через меню «Переменные среды системы» (Windows):

| Переменная             | Значение                          | Описание                           |
|------------------------|-----------------------------------|------------------------------------|
| `OBSIDIAN_VAULT_PATH`  | `D:\Obsidian\MyVault`             | Путь к Obsidian vault              |
| `VAULTCTL_AGENT_CMD`   | `pi -p`                       | Команда запуска CLI-агента         |
| `VAULTCTL_TIMEOUT`     | `300`                             | Таймаут в секундах (опционально)   |

### Вариант Б: Флаг --env-file

```powershell
vlt --env-file "<путь-к-репозиторию>\.env" "сохрани ссылку https://..."
```

### Вариант В: Симлинк на .env в домашней директории

```powershell
# Создать .env в домашней папке, который vaultctl найдёт оттуда
copy "<путь-к-репозиторию>\.env.example" "$env:USERPROFILE\.env"
# и отредактировать под свои пути
notepad "$env:USERPROFILE\.env"
```

Но проще всего — **Вариант А**: единожды прописать `OBSIDIAN_VAULT_PATH` в
системные переменные, и забыть.

## Проверка

```powershell
# Должна показать справку — значит, команда найдена
vlt --help

# Запуск задачи из любой папки
vlt "что нового в проекте за сегодня"
```

## Как это работает

- `[project.scripts]` в `pyproject.toml` объявляет entry points:
  ```toml
  [project.scripts]
  vaultctl = "vaultctl.cli:main"
  vlt = "vaultctl.cli:main"
  ```
- `uv tool install --editable .` создаёт под vaultctl **отдельное** окружение в своём
  каталоге инструментов и кладёт команды `vaultctl` и `vlt` в `PATH`. Проектный `.venv`
  при этом не используется — это независимая установка.
- `--editable` означает, что окружение ссылается на исходники в этой директории: правки
  кода подхватываются сразу, без переустановки. А вот **новая зависимость** в
  `pyproject.toml` — нет: под неё нужен повторный `uv tool install --editable .`.
- CLI-агент запускается с `cwd=vault_path` и `OBSIDIAN_VAULT_PATH` в
  окружении, поэтому навык obsidian получает путь к vault без дополнительных
  настроек.

## Решение проблем

| Проблема                                        | Причина и решение                                                          |
|-------------------------------------------------|---------------------------------------------------------------------------|
| `vlt: команда не найдена`                       | `uv tool` не добавил `%USERPROFILE%\.local\bin` в PATH. Добавить вручную. |
| `Не удалось определить vault`                   | Не задан `OBSIDIAN_VAULT_PATH` — задать через `--env-file` или переменную.|
| `CLI-агент «claude» не найден`                  | Claude Code не установлен или не в PATH. Указать полный путь через `--agent-cmd`. |
| `файл .env не найден: ...`                      | Указан несуществующий `--env-file`.                                        |
