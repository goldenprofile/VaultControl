## Вердикт

**Ядро самодостаточно.** Каждый сценарий из описания навыка имеет отдельный
reference с workflow, форматами выходных заметок и подводными камнями; живые
прогоны подтверждают работу в среде pi без ручных костылей. Разрывы найдены, но
все — на границах (неинтерактивность, чужие имена инструментов), ни один не
делает сценарий невыполнимым.

## Разрывы

### 1. Неинтерактивный режим: предписания «спросить» без собеседника (главное)

Несколько мест предписывают диалог: obsidian-tasks — «если найден дубликат,
спроси, обновлять или создавать»; vault-zen — «подтверждай каждое деструктивное
действие», «если неясно — спроси, не угадывай»; «фазное исполнение с одобрением
между фазами». В интерактиве это правильно, но vlt гоняет агента unattended:
спрашивать некого. Модель ведёт себя недетерминированно — от безопасного отказа
до импровизации. **Живой пример:** «Создай задачу… Через неделю проверить CSP» —
после слов про autonomous run модель сама отказалась писать вне vault, но это
совпадение благонамеренности, а не правило.

→ *Рекомендация в llm-skills:* добавить в SKILL.md политику неинтерактивного
режима: «если пользователь недоступен для вопроса (headless-запуск) — выбирай
безопасный дефолт (архив вместо удаления, создание новой заметки вместо правки
дубликата), явно фиксируй выбор и альтернативы в итоговом отчёте».

### 2. Конвенция `task <проект>: …` не зафиксирована в дизамбигуации навыка

obsidian-tasks триггерится на «ProjectName: description» и «добавь задачу», но
`task` как префикс там не назван; SKILL.md → «Быстрая дизамбигуация» тоже.
Без явного правила модель может прочитать «task X: Редизайн Y» как задание
выполнить Y — живой пример: вместо заметки-задачи выполнен весь редизайн
(сниппет + синтез + MOC). Прикрыто расширением vlt-bridge (инжект дисциплины
«записать, не выполнять»), но это знание живёт не в навыке.

→ *Рекомендация в llm-skills:* в дизамбигуацию и триггеры obsidian-tasks
добавить «task <проект>: …» с пометкой «зарегистрировать задачу, работу не
выполнять» — тогда навык поведёт себя одинаково в любом харнессе.

### 3. Имена инструментов из Claude Code

SKILL.md оперирует `Read/Glob/Grep/Write/Edit/Agent/WebFetch`. В pi это
`read/bash/grep/ls/…` — модель отображает сама (живые прогоны это подтвердили),
но два отображения не бесплатные:

- **WebFetch отсутствует** — навык честно помечает JS-heavy SPA вне ядра;
  статические страницы агенты берут `curl` через bash (работает), но качество
  извлечения ниже, и `--max-time` в команду надо не забыть.
- **`Agent` (субагенты) отсутствует** — батч-обработка пачки клиппингов
  вырождается в последовательные bash-циклы: медленнее, но корректно.

→ *Рекомендация в llm-skills:* переписать раздел «Инструменты» в терминах
возможностей («файловое чтение», «поиск по имени/содержимому», «терминал»,
«загрузка URL — штатным инструментом или curl») вместо имён конкретного
харнесса; пометить субагентов как «если доступны».

### 4. Очень большие входные материалы

Разбор 58 КБ ROADMAP или 100+ файлов zen-аудита упирается в лимиты контекста и
время: референсы дают глубину по размеру выборки (vault-zen), но для длинных
документов (разбор ROADMAP по пунктам → пачка задач) рекомендаций нет. Первая
попытка живьём ушла в блуждания по диску ещё до открытия файла — задача без пути
+ большой файл.

→ *Рекомендация в llm-skills:* секция «большие материалы»: сначала оглавление,
потом целевые секции; длинный разбор — сразу в пачку задач/заметок частями, а не
одним ответом. Пользовательская практика: указывать путь к файлу явно.

### 5. Мелочи

- `curl` без `--max-time` в клиппинге может подвесить ход на минуты (наблюдалось
  косвенно); в obsidian-clippings стоит предписать таймаут явно.
- Скрипт `html2md.py` вызывается по абсолютному пути — живьём работает; в
  reference можно уточнить, что путь к навыку агенту сообщает харнесс.

## Итог

Навык закрывает все десять задекларированных сценариев и оба ваших примера
поведения: «наведи порядок» → vault-zen с исполнением и triage; «запиши задачу в
проект» → obsidian-tasks с формулировкой и записью. Для усиления достаточно
трёх точечных правок в llm-skills (неинтерактивная политика, конвенция `task`,
инструментально-нейтральные имена) — vlt-bridge уже прикрывает вторую, третья
компенсируется моделью.
